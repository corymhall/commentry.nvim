*commentry.txt*  Local diff review workflows for Neovim

INTRODUCTION                                     *commentry*

commentry.nvim provides local diff review workflows inside Neovim with
draft persistence, typed/range comments, reviewed-file tracking, and an
optional provider-agnostic agent handoff path.
Minimum Neovim version: 0.10+.

UNIVERSAL INBOX                                   *commentry.inbox*

The project inbox works without Diffview or Snacks.

:Commentry comment
    Comment on the current file line. A command range captures the selected
    lines, for example :'<,'>Commentry comment. The multiline editor uses
    Ctrl-s or normal-mode Enter to save. Normal-mode Esc, q, or Ctrl-c cancels.
    Insert-mode Esc returns to normal mode.

:Commentry capture-text [register]
    Comment on copied text without a file anchor. Defaults to the unnamed
    register. Use + for the system clipboard when a provider is installed.

:Commentry inbox [all]
    Open project threads beside their focused source comparison. The default
    scope is the canonical Git worktree root, or the containing directory
    outside Git. The all scope includes every project. Branch provenance is
    recorded but does not filter threads. Worktrees have separate scopes.

:Commentry new-thread
    Create a standalone project conversation with no file or copied excerpt.
    Also available as n inside the inbox.

Inbox-local keys:
    j/k   Select a thread in the list.
    r     Focus the reply area beneath the conversation.
    visual r Quote selected source text into the reply.
    :write Save the inline reply. s sends after saving.
    n     New standalone thread.
    Enter Open the conversation and mark displayed messages read.
    u     Toggle read/unread.
    f     Filter all/unread/read/open/resolved/queued.
    m     Choose queue or steer send mode.
    s     Queue or send the selected thread.
    gs    Send all new project comments to the native agent queue.
    S     Attach an existing Pi or Codex session in this project.
    a     Attached session status, focus and delivery controls.
    t     Retry a failed request after inspecting partial work.
    d     Remove the oldest pending request from the selected thread.
    Ctrl-d Save and dispatch from the new-thread composer. Ctrl-s only saves.
    Ctrl-h/j/k/l Move between panels, keeping plain h/j/k/l for text.
    x     Resolve or reopen. The thread stays in the list.
    gl    Jump to a section in the unified source pane.
    gf    Go to code for the source section under the cursor.
    za    Fold or unfold a source section.
    e     Expand or collapse context from four to sixteen surrounding lines.
    i     Inspect thread ID, capture details and Git provenance.
    ?     Show inbox help.
    R     Refresh external writes and current file contents.
    q     Close the inbox tab.

gs sends open threads with new comments from You across the project's filters.
It submits one compact notification with the project, thread IDs and claim IDs.
The agent fetches the submitted context through Executor and answers each item
with finish. Captures and conversation bodies are not repeated in the paste.
In the all-projects view it uses the selected thread's project. Resolved threads,
agent-only notes and previously delivered comments are skipped. Existing pending
requests are delivered without adding copies. With no attached agent, requests
are saved for delivery. It reports counts and failures, or that nothing is new.
Failed requests require explicit retry after inspection. gs always uses queue
mode, independently of m.

Replies are edited directly in the thread buffer below the Reply heading.
Use :write to save a comment, then s to send the saved conversation. Saving
again with an empty reply does not add a duplicate. Visual r in the source pane
quotes the selected text with > prefixes and places the cursor beneath it.
Diff markers remain in quotes; virtual line numbers are not included.
Drafts survive switches and inbox closure within the current Neovim session.
Dirty replies keep their displayed history fixed until saved. Saving reloads
new messages. Existing history cannot be changed through :write. Undo edits
above the reply heading before saving. Failed saves retain the draft.
The thread buffer keeps normal i/a/u/d/x and other text-editing keys. Filtering,
resolution and other inbox actions remain available in the list/source panes.

Native window commands that close a panel also close the inbox view. Reopen it
with :Commentry inbox. Every comparison appears in the source pane with its
label and author. The conversation begins with its current review summary,
when present, followed by discussion.

Copied questions and notes can acquire code locations without replacing their
original text. Agents use attach with a label and a file source snapshot. The
source includes a project-relative path, one-based first/last lines, the entire
file's lines and optional filetype, modified and Git metadata. attachment_id
replaces a previously read location with the same ID. Agent attachments become
unread without resolving the thread.

Agents may instead attach an excerpt with excerpt_first, the absolute file line
of lines[0]. first/last remain absolute selection coordinates, contained within
the excerpt. Omitted excerpt_first means the entire file starts at line 1.
Unchanged excerpts follow unique code matches. Changed or ambiguous matches
stay visible as saved excerpts and gf does not guess a destination. Neovim's
file selections continue to capture full snapshots automatically.

The source pane contains saved comparisons, every code attachment and original
context together. The chosen primary comparison appears first and supporting
evidence starts folded. Without a choice, the first saved comparison stays
first when more evidence arrives. Comparisons may describe a proposal rather
than current code. Code sections show current local excerpts or a diff
labeled Changed locally since attached. Missing files retain a Saved snapshot.
Original code context and long copied excerpts start folded. Use za to toggle
sections. Fold choices survive refreshes. There is no comparison mode picker.

Agents use revise to maintain a current review title and summary above the
discussion. primary_comparison selects a saved comparison by ID. An update
requires expected_review equal to the current review ID. The original capture
and chronological messages stay intact. The original agent finding starts
folded when its current review replaces it. Human messages stay visible.
comparison_id replaces an agent's own comparison at its existing ID. Prior
review and comparison versions remain in history. These updates become unread
without resolving the conversation or rewriting submitted requests.
archiveComparison withdraws an agent's own comparison from the active view,
retaining it in history and clearing its primary selection when needed.

Press gl to jump to a section. gf opens current code for the source section
under the cursor, in the editing window you came from. Saved comparisons
without code locations never guess a file. From another panel gf uses the source
section or the first code location. Changed or ambiguous destinations stay in
the inbox. Visual r quotes carry the section's location or descriptive label.
Code buffers show gutter markers for open threads loaded from the inbox.
The active thread also has a range highlight and short reply preview.
Markers track edits using cached snapshots. Refresh the inbox for new activity.
gC in a visited code buffer opens its thread, or a picker when threads overlap.
It is installed only when the key is free. <Plug>(CommentryThread) supports your
own mapping.

File captures preserve the entire buffer, including unsaved changes, selected
range, and available Git HEAD, branch and original blob. The source pane shows
the relevant surrounding region. Edited selections remain visible as Outdated
with an approximate diff. Missing files retain the original excerpt. Original
captures never change. Conversation resolution and location state are separate.
Narrow editors stack source and conversation beside the list.
At 140 columns and above they sit side by side. Resizing adapts the layout.
Commentry does not set a colorscheme. Use your normal Neovim configuration to
inherit its theme and integrations.
Titles and compact location/status labels keep the inbox scannable. Diffs show
original/current line numbers and theme-linked addition/deletion highlights.
Conversation headers emphasize authors with quiet timestamps. Provenance is
available through i. CommentryInbox highlight groups inherit the colorscheme.

Unread activity is marked *. Incoming messages/attachments/comparisons have an author other
than You. Own replies do not clear unread activity. List previews never mark a
thread read. Enter or entering the conversation panel acknowledges only the
displayed incoming version. New concurrent replies remain unread. CLI read is
non-consuming. Use u to toggle read/unread. :Commentry inbox unread opens a
project filter. The other project filters are read, open, resolved, queued.
Use :Commentry inbox all then f to filter all projects. A read thread remains
visible in the unread filter until R or a filter change. External writes refresh
about every 1.5 seconds in normal mode while the inbox is active, preserving
selection and scroll position.

S selects an existing Pi or Codex process in Rex, scoped to this project.
Rex supplies discovery, status and terminal input for the existing agent.

Load the general-purpose actions in Rex init.lua, then rex config reload:
>
  dofile(os.getenv("HOME") .. "/plugins/commentry.nvim/integrations/rex/agents.lua").setup()
<
These actions also work independently of Commentry:
>
  rex do agent_list
  rex do agent_list project=/absolute/project/path
  rex do agent_get target=TARGET_ID_FROM_LIST
  rex do agent_queue target=TARGET_ID_FROM_LIST text='Review this'
  rex do agent_steer target=TARGET_ID_FROM_LIST text='Also check cancellation'
  rex do agent_read target=TARGET_ID_FROM_LIST
  rex do agent_focus target=TARGET_ID_FROM_LIST
<
Targets identify session, pane and foreground process. Restarting or replacing
the agent requires selecting its new target. agent_list filters by an absolute
directory and descendants. Commentry additionally resolves Git roots. The
picker prefers agents in the current worktree. If none is found, it shows agents
in other worktrees of the same repository, excluding separate clones.
agent_get returns status. agent_read returns terminal text, not a structured
conversation transcript. OpenCode is not implemented.

Queue and steer both submit immediately, including while working. Codex uses
Tab for its native queue and Enter for steering. Pi uses Alt-Enter for native
follow-ups and Enter for direct submission. An idle agent may start immediately.
The harness owns scheduling. No Commentry worker waits for idle or starts agents.
Messages use bracketed paste followed by the submission key in one PTY write.
The existing composer should be clear of unfinished drafts. Blocked, unknown or
error states require attention before sending. Agent status must be reported by
the foreground process. Approvals and questions stay in the agent interface.

Customized keybindings can be supplied as terminal byte sequences:
>
  dofile("/path/to/agents.lua").setup({ adapters = {
    codex = { queue = "\t", steer = "\r" },
    pi = { queue = "\27\r", steer = "\r" },
  } })
<
Commentry keeps immutable snapshots, inbox thread IDs and claim IDs. Requests
include instructions for finish through the CLI or JSON RPC, saving the reply
and completing the claim atomically. Terminal writes and status changes do not
complete inbox requests. Pending means locally waiting for delivery, Sent means
submitted to the harness. Completion does not resolve conversations. Comparisons
can be attached through the CLI while preserving the original capture.

Sending an unchanged active request shows "Nothing new to send. There are no
new messages." Without a selected agent, requests remain locally pending.
Selecting an agent
or using a to deliver pending requests sends them to its native queue. Press a
for status, focus, selection or detach. Detaching leaves delivered work intact.
Failed or partial writes are never replayed automatically. Inspect the agent
before retrying with t. Sending the same failed snapshot keeps its failure
visible. A late agent answer can finish its original claim until explicitly
retried. Cancelling a delivered inbox claim does not remove work
from the harness's native queue.

Rex clipboard capture:
Install the binary with mise run install-commentry. In Rex init.lua:
>
  dofile(os.getenv("HOME") .. "/plugins/commentry.nvim/integrations/rex/commentry.lua")
  rex.bind("ctrl+a>a", "commentry_capture")
  rex.bind("ctrl+a>shift+a", "commentry_new")
  rex.bind("ctrl+a>i", "commentry_inbox")
<
The first action snapshots the macOS clipboard, reads the originating pane's
project directory, and opens a temporary New comment tab. Captured text appears
above a multiline editor using your Neovim configuration and theme. Ctrl-p
changes project. Ctrl-s saves. Ctrl-d saves and queues. Normal-mode q or :q
cancels. Saving or cancelling returns to the originating tab. Failed saves
retain the draft. The second action starts without a clipboard attachment.
If sending fails after saving, the editor stays open with delivery guidance.
Ctrl-s closes the saved capture. Inspect the inbox before retrying delivery.
commentry_inbox reuses Neovim in the current pane or an immediately adjacent
pane to the left or right in the same Rex window. Otherwise it creates a
right-hand pane and starts Neovim there. Existing editors use RPC when available,
otherwise a Normal-mode command.
Both paths retain unsaved buffers and the working directory. Invoking from
a recognized agent pane selects that agent for the project without submitting
pending requests. The equivalent shell command is commentry rex inbox.
The Lua entry point accepts an explicit project:
>
  require("commentry.inbox").open(nil, { project = "/path/to/project" })
<
The bindings work while Rex is focused, not as OS-wide hotkeys.

The same composer runs with commentry capture --project . or --empty.
commentry rex capture opens it in Rex using REX_SESSION and REX_BLOCK.
Use --client when several Rex apps are connected. COMMENTRY_REX overrides
the Rex executable. Capture currently requires local macOS and Neovim 0.10+.

Existing session commands:
>
  commentry agent --project . list
  commentry agent --project . attach TARGET_ID_FROM_LIST
  commentry agent --project . status
  commentry agent --project . dispatch
  commentry queue t-THREAD --defer-delivery
  commentry agent --project . dispatch-batch --queue-id e-REQUEST --queue-id e-OTHER
  commentry agent --project . steer t-THREAD
  commentry agent --project . detach
  commentry retry t-THREAD --queue-id e-REQUEST
  commentry finish t-THREAD --claim-id claim-ID --author codex --body 'Reply'
<
There is one selected existing session per project. Selection is independent
of delivered work. All discovery and delivery go through the Rex actions.
Agent payloads retain original first/last selection coordinates. excerpt_first
maps lines[0] to the original file line in a focused excerpt.

External agents and capture tools can invoke scripts/commentry-inbox from the
plugin checkout. It reads one JSON request from stdin and returns one JSON
response, by forwarding to the Go backend with commentry rpc. Neovim is not
required by the external CLI. Build with mise run build or install with
mise run install-commentry. The inbox uses bin/commentry from the checkout,
then commentry on PATH. Override the executable with COMMENTRY_CLI.
Supported requests include:
>
  {"action":"create","project":"/project","text":"excerpt","body":"comment"}
  {"action":"list","project":"/project"}
  {"action":"read","thread":"t-..."}
  {"action":"reply","thread":"t-...","author":"Agent","body":"reply"}
  {"action":"comparison","thread":"t-...","author":"Agent","label":"Refactor","before":"old\n","after":"new\n"}
  {"action":"resolve","thread":"t-...","resolved":true}
  {"action":"list","project":"/project","filter":"unread","summary":true}
  {"action":"read-state","thread":"t-...","read":true,"seen":"e-incoming-version"}
  {"action":"queue","thread":"t-..."}
  {"action":"claim","project":"/project","author":"Agent"}
  {"action":"complete","thread":"t-...","claim_id":"claim-..."}
  {"action":"cancel","thread":"t-...","queue_id":"e-..."}
<
Creation returns the stable thread ID as result. Project defaults to the
invoking directory for create. Omit project from list to list every project.
Comparison text is stored verbatim and never edits source files. All attached
comparisons appear automatically in the source pane, each labeled with its
author and timestamp.
Authors are caller-provided labels. Failed requests return ok=false and exit
nonzero. R refreshes incoming messages. FocusGained also refreshes the inbox.
summary excludes full snapshots from list output. Claims are project-scoped and
serialized, and return an immutable message. Completion does not resolve the
thread. Claimed work remains visible until completed, explicitly cancelled,
or explicitly marked failed after uncertain delivery.
SQLite transactions recover incomplete writes after a crash. Committed claims
are never automatically reassigned.

The Executor Commentry app owns the configured inbox in its SQLite database.
Neovim and the Go CLI call the same operations agents use through codemode.
Local capture, Git comparisons and Rex terminal delivery stay on this machine.
Executor never starts local agent sessions. Sign in with:
>
  commentry executor login --url https://YOUR_EXECUTOR --organization ORGANIZATION --app APP_ID
  commentry executor status
<
Approve the browser link and code printed by login. The session grants Executor
API account access. Credentials refresh automatically and stay in private local
files. Neovim uses the same session through its CLI adapter.

Connection files are stdpath("data")/commentry/inbox/executor.json and
executor-session.json. COMMENTRY_INBOX_DIR and --directory select another
connection directory. The standalone CLI respects NVIM_APPNAME and defaults to
$XDG_DATA_HOME/nvim/commentry/inbox or ~/.local/share/nvim/commentry/inbox.
An unconfigured directory retains the legacy SQLite backend for migration and
isolated tests. A configured remote never falls back to local writes.
Unavailable Executor reports an error. Offline capture is deferred.

Keep other inbox clients idle during migration. Export the local inbox before
login, keep the backup, then import after connecting:
>
  commentry executor export > inbox-backup.json
  commentry executor import --file inbox-backup.json
<
Import preserves IDs, timestamps, source captures, messages, requests and read
and resolution state. Conflicts abort the batch. Local SQLite and earlier
prototype event files remain untouched. Removing connection files does not
delete the Executor inbox. There is no deletion interface yet.

Agents discover the installed Commentry app in Executor codemode. Its native
tools are publish, publications.read, requests.read, requests.context, list, read, create, reply, finish,
attach, comparison, archiveComparison, revise, resolve, readState,
changes and revision. finish atomically replies and completes the supplied
claim_ids without resolving the thread. reply only adds a comment. The packaged
commentry skill describes the flow. Local canonical checkout paths remain the
project identities; different machines' paths are not automatically linked.

publish atomically saves 1 to 25 independent topics with current summaries and
evidence. Supply project, request_id, author and items. Each item has a unique
key, title and body, with optional source, attachments and comparisons.
Comparison keys are local to the item; primary_comparison selects one by key.
The response maps topic keys to saved thread/evidence IDs without echoing code.
There is no need to create then revise each new thread separately.

Persist the manifest and request_id before submitting. publications.read looks
up a completed receipt by project/request_id. If a response is lost, retry only
the exact original ID and payload. That returns the original IDs without
overwriting later replies or creating copies. Changed content at the same ID
is rejected. A missing status while an earlier call runs does not prove failure.
All topics commit together or none do. Executor approval/input pauses still use
resume rather than repeating the publication.

For delivered comments, requests.read accepts the exact project and items from
the notification. It returns five claims per page and up to 2000 Unicode
characters per context. next_cursor continues the batch; requests.context uses
context.next_offset to continue one request. History and source sections expose
more submitted context. Comparison sections expose current enrichment. Later
replies never enter the saved submission. Inactive claims return status only.
Full read remains available for explicit complete-thread inspection.
When wrapping MCP, emit checked execution.value, avoiding duplicated envelopes.

The standalone binary exposes list, read, create, reply, resolve, attach, comparison,
archive-comparison, revise, publish, publication,
read-state, queue, claim, complete, cancel, retry, revision, changes, watch, rpc,
capture, rex, agent, and executor.
All data commands return JSON. Examples:
>
  commentry list --project . --filter unread --summary
  commentry create --project . --body "Explain this" --text "Copied output"
  commentry reply t-THREAD --author Codex --body "Here is the answer"
  commentry claim --project . --author Codex
  commentry complete t-THREAD --claim-id claim-CLAIM
  commentry attach t-THREAD --author Codex --label Implementation --source-file capture.json
  commentry comparison t-THREAD --author Codex --label Refactor --before-file old.lua --after-file new.lua
  commentry publish --file review.json
  commentry publication --project . --request-id REVIEW-ID
  commentry watch --project . --after 0 --timeout 60s
<
watch emits an initial JSON page, then streams committed changes until cancelled
or the optional timeout expires. Resume with --after CURSOR from the same
database. changes --after CURSOR returns up to 100 changes with a cursor and
revision. JSON equivalents are action=changes with cursor, and action=revision.
Reading and watching do not mark messages read. read-state --read --seen
e-VERSION acknowledges only the displayed incoming version; --read=false marks
unread. Authors are caller-provided labels, not authentication.

This first implementation has separate inbox and Diffview review stores.
Review linking, OpenCode, anchor reattachment,
branch comparison mode and an OS-wide capture shortcut are not implemented yet.

INSTALL                                           *commentry.install*

Required dependencies:
    Neovim 0.10+, the Commentry CLI and the Commentry Executor app.
    Configure the connection with commentry executor login/use.

Optional integrations:                           *commentry.dependencies*
    diffview.nvim for capture from Git changes.
    Rex for external capture and delivery to existing agent panes.

SETUP                                             *commentry.setup*
>
    require("commentry").setup({
      diffview = { enabled = true, auto_attach = true },
      keymaps = {
        add_comment = "mc",
        add_range_comment = "mc",
        list_comments = "ml",
      },
    })
<
DIFFVIEW AND AGENTS                                *commentry.agent*

:Commentry open [arguments] opens Diffview. Direct :DiffviewOpen also attaches
Commentry when auto_attach is enabled. Both sides save to the shared inbox,
including staged, base, deleted and renamed file versions. Captures retain the
displayed text, path and revision. Empty and binary sides cannot be captured.

mc opens the inbox composer. Visual mc captures the selected lines. Ctrl-s
saves to the inbox. Persistent boxed multiline comment cards appear below the
code, with range gutter marks and subtle line highlighting. Cards follow the
latest reply. gC opens the full thread.
ml opens the project inbox. All replies, resolution, read state and Rex delivery
use that same inbox. Changed and missing locations remain saved conversations.
Sidekick and the separate draft-review handoff have been removed.

KEYMAP CONFIG                                     *commentry.keymaps*

    add_comment       mc    Normal, capture current line
    add_range_comment mc    Visual, capture selected range
    list_comments     ml    Normal, open project inbox

Empty strings disable a mapping. Set diffview.auto_attach=false to disable
Diffview integration. These mappings only attach to Diffview file buffers.

Visual settings under diffview:
    comment_cards.max_width       76
    comment_cards.max_body_lines  6
    comment_cards.show_markers    true
    comment_ranges.enabled        true
    comment_ranges.line_highlight true

Long cards show a continuation hint. gC opens the full conversation. Card and
range highlights follow the current theme.

PERSISTENCE                                       *commentry.persistence*

All conversations live in the configured Executor inbox. Captures are immutable,
thread IDs survive source changes and resolution is independent of location.
The branch-scoped commentry.json store is no longer loaded or written. Existing
~/.commentry files remain untouched. There is no automatic import. The old draft
picker, types, reviewed-file tracking and export commands have been removed.

TROUBLESHOOTING                               *commentry.troubleshooting*

Run :checkhealth commentry for CLI readiness. Configure Executor before capture.
Use :Commentry diagnostics for the selected connection directory and executable.
Changed or deleted source remains in the inbox. Agents may attach current code
without replacing the original capture. Delivery uses existing Rex agent panes.
